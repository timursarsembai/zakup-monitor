# zakup

Мониторинг объявлений и лотов портала госзакупок Казахстана (goszakup.gov.kz)
через его API (`ows.goszakup.gov.kz/v3`). Сейчас это инструмент для себя, но
схема рассчитана на то, чтобы потом сделать из него сервис для многих
пользователей.

## Как устроено

- **worker** — раз в 10 минут забирает новые объявления (`/v3/trd-buy`) и лоты
  (`/v3/lots`). API отдаёт их от новых к старым, поэтому сборщик идёт сверху вниз
  до уже загруженного; прерванный проход продолжается с того же места. Затем проверяет
  подписки и отправляет совпадения в Telegram. Потом шаг `details` через
  GraphQL дочитывает у открытых объявлений то, чего нет в REST-списке:
  признак «среди организаций инвалидов», места поставки (КАТО) и аванс.
- **web** — FastAPI с серверными шаблонами: поиск по лотам (полнотекстовый,
  русская морфология), подписки и найденные совпадения. Вход по e-mail и
  паролю (scrypt), сессия в cookie на 30 дней, подбор пароля ограничен.
  Регистрации нет: пользователей заводит `zakup set-password <email>`.
- **postgres** — всё хранится здесь. Запись из API целиком лежит в `raw jsonb`,
  а нужные поля разложены по колонкам. Поэтому новые поля можно добавить без
  повторной загрузки.

Чтобы не тянуть всю историю (это 13 млн объявлений), команда `start-from`
бинарным поиском по id находит первое объявление нужной даты. Без неё
сборщик при первом запуске берёт последние 7 дней.

## Запуск

Секреты живут в Infisical (https://infisical.sarsembai.com, проект `zakup`,
окружение Production). `scripts/fetch-secrets.sh` переносит их в `.env`
поверх локальных значений. Машинная учётка `zakup-server` (роль Viewer) лежит
в `~/.config/infisical/zakup.env`.

```bash
cp .env.example .env              # пароль Postgres
./scripts/fetch-secrets.sh        # GOSZAKUP_TOKEN и прочее из Infisical
docker compose build
docker compose run --rm --entrypoint zakup worker probe          # токен работает? какие поля?
docker compose run --rm --entrypoint zakup worker migrate
docker compose run --rm --entrypoint zakup worker start-from 2026-10-01   # необязательно
docker compose up -d
docker compose exec -it worker zakup set-password you@mail    # спросит пароль
```

Веб-интерфейс открывается на `127.0.0.1:8096` (шлюз `zakup-web`; за ним две копии сайта `web` и `web-2`, `scripts/deploy.sh` перезапускает их по очереди — выкладка без перерыва). Наружу его выставлять через Nginx
Proxy Manager.

Telegram: токен бота (`ZAKUP_TELEGRAM_BOT_TOKEN`) в Infisical, username
(`ZAKUP_TELEGRAM_BOT_USERNAME`) в `.env`. Сервис **bot** опрашивает Telegram и
привязывает чаты: на странице «Настройки» кнопка «Подключить Telegram» даёт
одноразовую ссылку `t.me/<бот>?start=<код>` на 30 минут. Совпадения рассылает
worker сводками (до ~3800 символов в сообщении, не чаще раза в секунду в чат);
если пользователь заблокировал бота, чат отвязывается. `ZAKUP_TELEGRAM_CHAT_ID` —
чат владельца для служебных оповещений.

## Поиск: лоты и объявления

Две страницы с полями как в поиске портала, логика — `zakup/filters.py`:

- `/lots` — поиск лотов: таблица «№ лота, объявление и заказчик, наименование
  и описание, количество, цена за единицу, сумма, аванс, способ, статус».
  Сумма, аванс, место поставки, статус, номер лота и ЕНС ТРУ — у лота; признак
  «среди организаций инвалидов», способ, предмет, финансовый год и даты — у
  объявления. Отметки, «Не подходит», Excel и сохранение как подписку — здесь.
- `/announcements` — поиск объявлений: «№ и число лотов, наименование и
  организатор, способ, начало и окончание приёма, сумма, статус».

Статус выбирается этапом («Идёт приём», «Рассмотрение», «Итоги подведены,
есть победитель», «Не состоялась», «Отменено») или точным статусом портала.
Если выбраны только статусы приёма заявок, объявления с прошедшим сроком
отсекаются: портал меняет статус с опозданием.

По умолчанию: статус 240 «Опубликовано (прием ценовых предложений)», закупка
среди организаций инвалидов, г. Алматы (КАТО 75…) или Алматинская область
(19…), от 300 000 ₸, окончание приема ровно через 2 рабочих дня (пн → ср,
чт → пн, пт/сб/вс → вт), с авансом выше — первыми.

Подписаться можно на любой поиск без конкретных дат (срок «через 2 рабочих
дня» или без ограничения): с «Лотов» приходят подошедшие лоты, с «Объявлений» —
объявление целиком. Подписка шлёт в личный Telegram или в подключённую группу
(бот добавляется ссылкой `t.me/<бот>?startgroup=<код>` из настроек). Лоты одного
объявления приходят одним блоком; один лот в один чат — один раз (`chat_lots`),
даже если подошёл под подписки нескольких людей.

## Страницы объявления и лота

`/a/<id>`: шапка как на портале (статус, способ, даты, организатор, сумма,
обратный отсчёт), лоты с ценой за единицу, авансом, местом и сроком поставки,
текст технической спецификации из PDF (`zakup/spec.py`, грузится по клику и
кэшируется в `lot_specs`), документация, протоколы, победители (из протокола
итогов, `zakup/results.py`), договоры и апелляции. Данные открытого объявления
перечитываются с портала, если им больше 15 минут.

`/lots/<id>`: тот же лот отдельно — с объявлением сверху, итогами и
таблицей остальных лотов объявления.

## Поиск товаров с ИИ

На странице лота — «Найти товары»: ИИ читает техспецификацию, ищет в
интернете подходящие товары (сначала в регионе поставки, потом по
Казахстану) и возвращает таблицу: фото, товар, продавец, цена, цена за
единицу, ссылка. Маржу (в тенге, в %, на весь лот) от цены в лоте считает
сайт. Задачи — таблица `lot_research`, код — `zakup/research.py`.

Кто ищет — выбирает пользователь в настройках:

- **Claude Code по подписке владельца** (по умолчанию). Работает на хосте,
  не в Docker, — там установлен и авторизован `claude`. `claude -p` с
  инструментами WebSearch/WebFetch, без доступа к файлам и командам.
  Установка службы:

  ```
  python3 -m venv --without-pip .venv-host
  curl -fsSL https://bootstrap.pypa.io/get-pip.py | .venv-host/bin/python
  .venv-host/bin/pip install -e .
  ln -sf ~/apps/zakup/deploy/zakup-research.service ~/.config/systemd/user/
  systemctl --user daemon-reload && systemctl --user enable --now zakup-research
  ```

  После изменения кода: `systemctl --user restart zakup-research`.
- **Anthropic API / OpenAI API** с ключом пользователя — сервис `research` в
  docker compose. Ключи хранятся зашифрованными (`ZAKUP_SECRET_KEY`, Fernet).

## Языки

Интерфейс на русском и казахском: переключатель в шапке (cookie
`zakup_lang`). Тексты в шаблонах и коде — по-русски в `_()`, перевод —
словарь `zakup/i18n_kk.py` (ключ — русский текст; нет перевода — русский).
Данные портала на казахском — из полей `*Kz`/`name_kz`, техспецификации —
`lot_specs.text_kk`. Сообщения в Telegram — сразу на двух языках.

## Сбор данных

- `worker` — раз в 2 минуты: новые объявления, повторный проход за 3 дня,
  подробности открытых, совпадения, рассылка, напоминания, итоги.
- `archive` — раз в 15 минут: повторный проход за 30 дней, подробности
  завершённых, протоколы итогов.
- `specs` — постоянно: текст техспецификаций открытых лотов (рус. и каз.),
  PDF не хранятся.
- Страницы объявления и лота портал не ждут: данные из базы, устаревшие
  обновляются в фоне после ответа.

## Подписки на слова

Запрос пишется в синтаксисе `websearch_to_tsquery`: `картридж тонер` — нужны
оба слова, `картридж or тонер` — хотя бы одно, `-аренда` — исключить слово,
`"бумага а4"` — искать фразу. Слова сопоставляются по основе («картриджи»
найдётся по «картридж»). Новая подписка срабатывает только на лоты, которые
придут после её создания.

## Дежурный: автоисправление сбоев

Сборщики при ошибке пишут её в таблицу `incidents` и коротко сообщают владельцу.
Недоступность портала goszakup ошибкой не считается: о ней одно сообщение, если перерыв
длится больше 30 минут, и одно — когда портал вернулся.

Служба `zakup-autofix` на хосте (как и поиск товаров — через авторизованный `claude`)
берёт новый сбой и запускает Claude Code в репозитории. Тот ищет причину и решает:
- ошибка в коде — исправляет, гоняет `scripts/test.sh`, коммитит, пушит и выкладывает;
- причина снаружи — ничего не меняет;
- нужно решение владельца — откатывает свои правки.

Отчёт приходит в Telegram. Ограничители:
- один сбой за раз;
- не больше 6 запусков в сутки;
- после двух неудач с той же ошибкой — только владельцу;
- пока в репозитории есть незакоммиченные правки, служба ждёт.

```bash
cp deploy/zakup-autofix.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now zakup-autofix
journalctl --user -u zakup-autofix -f
```

Модель — `opus` (переменная `ZAKUP_AUTOFIX_MODEL`).

## Тесты

`scripts/test.sh` — сборка образа и все тесты на базе `zakup_test`. Код выхода ненулевой, если тест упал.


```bash
docker exec zakup-postgres createdb -U zakup zakup_test   # один раз
docker compose run --rm --no-deps -e TEST_DATABASE_URL=postgresql://zakup:<pw>@postgres:5432/zakup_test \
  --entrypoint pytest worker -q -p no:cacheprovider
```
