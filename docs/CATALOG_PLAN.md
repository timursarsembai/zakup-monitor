# Каталог товаров и продавцы — план (согласован 2026-11-12)

Задача владельца: у каждого товара каталога — своя страница; пользователи выкладывают свой каталог
через кабинет; у каждого продавца — своя страница с его каталогом, фильтрами и категориями.
Это продолжение раздела 3 ROADMAP («Маркетплейс поставщиков») — по сути отдельный сервис.

## Что есть сейчас

- `product_catalog` (миграция 0027): ~100 товаров из ИИ-подбора — название, продавец (текстом),
  город, телефон, картинка (ссылка на чужой сайт), цена, единица, характеристики, категория
  (раздел ЕНС ТРУ), в каких лотах находили, история цены. Страница `/products` — только сотрудникам.
- Загрузка картинок уже есть для логотипа (Pillow, проверка формата, ≤ 900 КБ) — в базе (base64).
- Пользователь = тендерщик (вход по телефону, подписка). Продавцов как сущности нет.

## Этапы

### Этап 1. Страница товара (небольшой) — сделано

- `/products/{id}-{slug}` — название, фото, цена на дату и её история, характеристики, продавец
  (ссылка), город, телефон, «найден в лотах» (ссылки на лоты), похожие товары (та же категория,
  похожее название).
- Строка таблицы `/products` ведёт на страницу товара; продавец — ссылка на страницу продавца.
- Пока каталог только у сотрудников — и страницы только сотрудникам. Открыть всем (и поисковикам)
  — решение владельца (вопрос 1).

### Этап 2. Продавцы — сделано (zakup.sellers)

- Таблица `sellers`: название магазина, slug для адреса, БИН/ИИН (необязательно), телефон(ы),
  WhatsApp, e-mail, сайт, город, регионы доставки, описание, логотип; источник: `user` (свой
  продавец, ведёт пользователь) или `found` (найден ИИ-подбором, без владельца).
- Найденные ИИ продавцы — по домену/названию из `product_catalog.seller` и `seller_contacts`;
  `product_catalog.seller_id` — ссылка. Если пользователь потом подтвердит, что это его магазин
  (по БИН или по сайту), — передаём ему (вопрос 4).
- `/sellers/{slug}` — карточка продавца и его каталог: поиск, категории (дерево ЕНС ТРУ по
  первым цифрам — как разделы в фильтрах закупок), цена от–до, город, «в наличии», сортировка.
- `/sellers` — список продавцов с поиском и фильтром по региону и категории.

### Этап 3. Свой каталог в кабинете — сделано без Excel и фото (zakup.shop, /my/shop)

Как сделано: свои товары — в том же `product_catalog` (`own`, `on_sale`, описание, код ЕНС ТРУ),
цены по количеству — `product_prices`; магазин с БИН из реестра (legal_entities/subjects) —
«проверен» и виден сразу, иначе ждёт сотрудника (`/staff/sellers`); там же заявки «Это мой
магазин» (`seller_claims`) — одобрение передаёт найденный магазин пользователю, его прежний
магазин сливается. В ИИ-подбор свои товары пока не идут — этап 5.


- «Кабинет → Мой магазин»: кнопка «Стать продавцом» → форма магазина (название обязательно,
  контакты — хотя бы один телефон). Тот же пользователь остаётся тендерщиком.
- «Мои товары»: список, добавить / изменить / снять с продажи / удалить.
- Карточка товара: название*, категория (выбор из ЕНС ТРУ с поиском; код ЕНС ТРУ — по
  желанию, точнее подбор под лоты), описание, характеристики (пары «название — значение»),
  единица измерения*, фото (до 8), наличие, цены*.
- **Цены** (обязательно хотя бы одна):
  - розничная (за единицу) — обязательна;
  - оптовые — ступени «от N единиц — цена за единицу», сколько угодно ступеней; проверка:
    N растёт, цена не растёт;
  - всё в тенге, с НДС или без — галочка у продавца (для тендерщика важно).
- Таблица цен `product_prices (product_id, min_qty, price)`: розница — `min_qty = 1`. В ИИ-подборе
  под лот берём ступень по количеству лота — сразу правильная оптовая цена в расчёте маржи.
- Импорт из Excel/CSV по шаблону (название, категория, единица, цена, оптовые ступени, ссылки
  на фото) — вторым шагом этапа.

### Этап 4. Фото — сделано (zakup.photos)

Как сделано: том `media` (сайт пишет в /data/media, шлюз раздаёт /media/p/… только по виду
имени `<32 hex>[_t].webp`), таблица `product_photos`, до 8 фото, главное — превью в
`product_catalog.image`. Предел запроса 45 МБ — только на `/my/shop/products/<id>/photos`.
**При выкладке:** добавить том `zakup_media` в `~/backups/make-backup.sh` (tar тома) — до
выкладки тома нет, и ночная копия ругалась бы каждую ночь.


- Хранение файлов: не в базе (каталог вырастет), а на диске сервера — том `media`, раздаёт
  nginx (`/media/...`). Сжатие при загрузке (Pillow): до 1600 px, WebP; превью 400 px.
  Проверка: только картинки (по содержимому, не по имени), размер ≤ 5 МБ, без EXIF (геометка).
- Предел запроса nginx сейчас 1 МБ — для загрузки фото поднять только на адресе загрузки.
- Резервная копия: том `media` — в ночную копию сервера (как база).
- Позже, если места мало, — объектное хранилище (S3-совместимое).

### Этап 5. Связь с закупками (главная ценность для сервиса) — сделано без расстояния (zakup.offers)

Как сделано: на странице лота (вкладка «Поиск товаров») блок «Есть у продавцов» — свои товары
по коду ЕНС ТРУ (код товара — начало кода лота) или словам названия в разделе, цена — ступень по
количеству лота, маржа; гостю и без подписки — только что есть. ИИ-подбор получает их первыми
(адрес — наша страница товара; телефоны — из магазина, в каталог не копируются). Оповещения
`zakup seller-alerts` (в круге archive): новые лоты по seen_seq, строже (код или все главные
слова), без повторов (`seller_alerts`), выключаются в «Моём магазине». Расстояние до места
поставки — позже.


- В лоте блок «Есть у продавцов»: товары каталогов по коду ЕНС ТРУ и названию, цена по
  количеству лота (оптовая ступень), продавец, город, расстояние до места поставки.
- ИИ-подбор сначала смотрит каталоги наших продавцов, потом интернет (как сейчас с
  `product_catalog`).
- Продавцу — подписка «появился лот на мой товар» (у нас уже есть подписки и Telegram): это
  повод продавцу вести каталог.

### Этап 6. Порядок и безопасность

- Модерация: новый продавец и товары видны сразу, но с кнопкой «Пожаловаться»; сотрудник
  может скрыть товар/продавца. Запрещённое — правила площадки (вопрос 5).
- Ограничения: товаров на продавца, загрузок в сутки; защита от спама (как у регистрации).
- Поисковики: страницы товаров и продавцов — в sitemap, разметка schema.org Product/Offer
  (цена, наличие) — по ним могут показываться расширенные сниппеты.

## Порядок работы

Этап 1 → 2 → 3 (без Excel) → 4 → 5 → импорт Excel → 6. После каждого этапа — выкладка и
проверка. Ориентир: этапы 1–2 — по одному заходу, 3–4 — самый большой, 5 — средний.

## Решения владельца (2026-11-12)

1. Страницы товаров и продавцов — открыты всем и поисковикам; маржа и связь с лотами — по подписке.
2. Выкладывать каталог — бесплатно на старте; платное (поднятие в лотах) — позже.

   «Это мой магазин».

6. Только тенге; «с НДС / без НДС» — галочкой у продавца.
