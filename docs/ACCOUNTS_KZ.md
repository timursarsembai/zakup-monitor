# Личные данные в Казахстане, остальное в Германии

Решение владельца (2026-11-13): тяжёлое (сайт, сборщики, аналитика, ИИ) — на сервере
в Германии под адресом tenderim.com; личные данные — только на сервере в Казахстане
(сервис учётных записей, id.tenderim.com). tenderim.kz — позже. Юриста нет.

## Что считается личными данными

Телефон (он же логин клиента), почта, хэш пароля, чат Telegram, сессии входа, IP-адреса
попыток входа и визитов, одноразовые SMS-коды. Сейчас это `users` и связанные таблицы
основной базы.

## Как устроено

- Форма входа рисуется на основном сайте, но отправляется на id.tenderim.com. Сервис
  проверяет пароль и ставит cookie `tid` на весь `.tenderim.com` — подписанный Ed25519
  жетон: номер пользователя, номер сессии, время выдачи (`zakup_id/token.py`).
- Основной сайт проверяет подпись открытым ключом сам — без запроса в Казахстан
  (связь Германия ↔ Казахстан ≈ 0,1 с, на каждой странице это было бы заметно).
- Жетон «свежий» сутки; старше — сайт обменивает его на новый (`POST /api/renew`).
  Так выход, смена пароля и блокировка доходят до сайта не позже чем через сутки.
  Если Казахстан недоступен, старый жетон принимается до 3 суток: сайт работает.
- Уведомления: сайт решает, кому и что, и отправляет «пользователю N — текст»
  (`POST /api/notify`); чат Telegram знает только сервис.
- В основной базе у пользователя остаются номер и настройки (подписки, тариф, роль, язык).

## Этапы

1. Домен tenderim.com (купить — владелец) → основной сайт; zakup.sarsembai.com — 301 на него.
2. Сервис учётных записей (`src/zakup_id`, `deploy/kz/docker-compose.yml`) — **начат**:
   вход, выход, продление жетона, «выйти везде», уведомление в Telegram. Дальше —
   регистрация и восстановление пароля по SMS, привязка Telegram, смена телефона/пароля.
3. Основной сайт на жетонах: проверка `tid`, продление, формы входа на id.tenderim.com,
   уведомления через сервис. Затем перенос данных, после проверки — удаление личных
   данных из немецкой базы и её копий. Переключение — с отдельного согласия владельца.

## Запуск в Казахстане (когда дойдёт)

    python -m zakup_id.keys >> deploy/kz/.env      # ключи — в файл, не на экран
    echo PROXY_NETWORK=<сеть nginx-proxy-manager> >> deploy/kz/.env
    echo ID_PROXY_IP=<адрес nginx-proxy-manager в этой сети> >> deploy/kz/.env
    docker compose -f deploy/kz/docker-compose.yml --env-file deploy/kz/.env up -d --build

Перенос учётных записей — с прежними номерами, затем `accounts.sync_ids`
(иначе счётчик новых столкнётся с перенесёнными).

Память: база до 192 МБ, приложение до 256 МБ. Копии базы — тоже в Казахстане.
