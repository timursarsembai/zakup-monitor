# Открытый API zakup.gov.kz — разведка 2026-11-12

Адрес: `https://zakup.gov.kz/api/core/api/public/`. Ключ не нужен. Проверено с нашего сервера.

## Общее

- Постраничный вывод — `limit` (до 100) и `offset` (не больше 10 000). Ответ: `count`, `next`, `results`.
  Параметров `page`/`page_size` нет.
- Неизвестный параметр → 400 `Unrecognized query parameters: …`, неверное значение → `Incorrect parameter
  values`. Так и проверяли, что принимается. Списки значений (`status_id=6,7`, `__in`) не принимаются.
- Темп: 20 запросов подряд без пауз — все 200, ~0,6 с каждый. Ограничений не видно, но портал общий:
  сборщик — 1 запрос в секунду.
- Свежее OWS: объявление появляется на платформе сразу, в OWS — через 10–20 минут.

## Объявления — `announcements/`

Фильтры: `system_id`, `status_id`, `purchase_method_id`, `purchase_subject_id`, `purchase_type_id`,
`organizer_id`, `announcement_number`, `single_organizer_type_id`, `is_among_disabled`,
`offer_start_date__gte`, `offer_end_date__gte`, `offer_end_date__lte`, `results_publication_date__gte`,
`total_price__gte`, `q` (поиск по словам). Сортировка: `ordering=-publish_date`, `id`, `-offer_end_date`.
Фильтра по дате публикации **нет** — новые берём сортировкой `-publish_date` до уже известного.

Поля списка: `id` (свой), `external_id` (id в исходной системе), `announcement_number`, `name`, `search_name`
(ru/kk), `system_id`, `status_id/name`, `purchase_method_id/name`, `organizer_id/name`, `total_price`,
`lot_count`, `publish_date`, `offer_start_date`, `offer_end_date`, `results_publication_date`.

Карточка `announcements/{id}/`: `customer`/`organizer` (`iin_bin`), `status` с кодами `egz_code`/`skk_code`/
`mtw_code`, `purchase_method` (`is_quasi`), `system`, `year`; даты — unix-время. Подкаталоги: `lots/` (весь
список одним массивом, без страниц), `protocols/` (у SKK пусто). Документов в открытом API нет.

## Лоты — `lots/`

Фильтры: `system_id`, `status_id`, `announcement_id`, `offer_end_date__gte`, `q`; `enstru_code` — нет.
Поля: `announcement_id/external_id/number/publish_date`, `name_ru/kk`, `description_ru/kk`, `enstrus`
(код, название, краткое описание), `quantity`, `total_price`, `customers` (`bin`, имя часто пустое),
`offer_start_date/end_date`, `status`, `purchase_method_id/name`.
Подробнее (в `announcements/{id}/lots/`): `plan_items` — цена за единицу, количество, единица (`measure`),
адрес поставки с КАТО, ЕНС ТРУ, предмет (товар/работа/услуга), аванс (`prepayment`, у SKK пусто).

`dumping_price`/`is_dumping` — **не порог демпинга**: бывает равен всей сумме лота, бывает похож на цену за
единицу. Наш расчёт порога (−10% по п. 94–98 Правил) не заменять.

## Самрук-Казына (система 3)

- Способы: ЗЦП (12), ЗЦП на понижение (63), открытый тендер (65), открытый тендер на понижение (66) — свои
  правила фонда, не Закон о госзакупках. Обеспечения/демпинг по ним считать нельзя без их Правил.
- Статусы: 6 «Опубликовано», 10 «Рассмотрение заявок», 80 «Подведение итогов», 16 «Завершено», 64 «Внесена
  поправка»; у лотов — итоговые («Закупка не состоялась» и др., `skk_code`).
- Заказчик: БИН есть всегда, **название часто пустое** (24 из 100 объявлений) и в OWS этих БИН нет.
  Источник названий — открытый реестр юрлиц data.egov.kz: `api/detailed/gbd_ul/v1?source=<запрос
  Elasticsearch>`, без ключа; `{"size":1000,"query":{"terms":{"bin":[…]}}}` — до 1000 БИН за запрос; ответ
  `{"totalCount", "data": [...]}`, поля `bin`, `nameru`, `namekz`, `addressru`, `director`, `okedru`,
  `statusru`, `datereg`; у БИН бывает несколько записей — берём самую свежую. ~1 млн записей.
  stat.gov.kz — только со входом; zakup.sk.kz — защита от роботов (не обходим).
- Способ 62 — «ЗЦП с ограниченным участием» (около 100 объявлений). Страница объявления на платформе —
  `https://zakup.gov.kz/announcement/{id}` (id платформы).
- Итоги: протоколов в открытом API нет; договоры есть — `contracts/?system_id=3` (906 тыс.), фильтр
  `announcement_number`; поля: поставщик, `contract_price_with_vat`, способ, статус. Победитель и цена — из
  договора.

## Mitwork (система 2)

Открытых всего 9, все «Тендер (не ГЗ)», организатор не указан; договоров 56 тыс. Ценность мала — после SKK.

## Что это значит для плана

1. Шаг «Сверка демпинга с платформой» — отменяется (`dumping_price` — не порог).
2. Сбор SKK: открытые лоты — `lots/?system_id=3&offer_end_date__gte=<сейчас>` (~50 запросов на все),
   новые объявления — `announcements/?system_id=3&ordering=-publish_date`, карточки — по одной для
   `plan_items`. Хранить с признаком системы; поиск, фильтр «Система», подписки.
3. Названия заказчиков SKK — найти источник до запуска (иначе в списке будут одни БИН).
4. Итоги SKK — из `contracts/` по номеру объявления.
5. Свежесть: можно брать свежие объявления госзакупок с платформы раньше OWS — отдельная мелочь, по желанию.
