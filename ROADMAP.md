## 4. Качество кода и безопасность

1. **Рефакторинг.** Сначала план (перегруженные файлы, функции, классы — например `web.py`), потом правки, чтобы проект было удобно поддерживать.
2. **Аудит безопасности уровня пентеста.** План, сам аудит с находками, разбор находок, план исправлений, исправления.
   Найдено на код-ревью 2026-11-08 и отложено до аудита:
   - вход: лимит неудачных попыток проверяется до записи попытки (параллельные запросы дают больше 5 попыток); блокировка по логину позволяет чужому держать аккаунт закрытым;
   - вход «как пользователь»: действия пишутся в журнал от имени клиента без пометки администратора; выход из чужого аккаунта не завершает сессию администратора;
   - длина пароля: 8 знаков при регистрации по SMS, 10 в настройках — свести к одному правилу;
   - клиенты добавляют источники в общий список для ИИ всех пользователей — модерация или свои у каждого;
   - выжимки и вопросы поставщику ждут модель с открытой транзакцией (как было у поиска);
   - sitemap содержит удалённые на портале лоты (страница отдаёт 404);
   - кнопка «Кратко» в техспецификации не видит уже готовую выжимку, если текст не был в кэше.

## 5а. Хранение данных

- Рост базы (замер 2026-11-08): около 43 МБ в сутки, 1,3 ГБ в месяц, 16–20 ГБ в год; свободно 71 ГБ.
- Примерно через полгода (весна 2027): у закупок, завершённых больше N месяцев назад, удалять
  тяжёлое — подробности (`announcements.detail`), тексты техспецификаций (`lot_specs.text`),
  исходные ответы портала (`raw`). Оставлять название, заказчика, сумму, сроки, итог. База в 2–3 раза меньше.
- Сжатие lz4 для больших колонок (`default_toast_compression`).
- Если станет тесно: старые годы — в сжатый архив на дешёвое хранилище, в базе только сводки.
- Историю 2026 года и сентябрь–октябрь не догружаем (решение 2026-11-08: аналитику не продаём,
  для SEO полезнее страницы организаций и подборки по категориям и регионам).

- Сделано 2026-11-08: каждый клиент видит только свои ИИ-поиски; сотрудники — все поиски по лоту одной таблицей без повторов; поиски покупаются только к оплаченному тарифу.
- Идея владельца на потом: тариф подороже, где клиент видит и чужие поиски по лоту (экономит на поисках). Решать по статистике: сколько людей ищут по одним и тем же лотам.
