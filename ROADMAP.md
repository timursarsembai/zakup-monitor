## 5а. Хранение данных

- Рост базы (замер 2026-11-08): около 43 МБ в сутки, 1,3 ГБ в месяц, 16–20 ГБ в год; свободно 71 ГБ.
- Примерно через полгода (весна 2027): у закупок, завершённых больше N месяцев назад, удалять
  тяжёлое — подробности (`announcements.detail`), тексты техспецификаций (`lot_specs.text`),
  исходные ответы портала (`raw`). Оставлять название, заказчика, сумму, сроки, итог. База в 2–3 раза меньше.
- Сжатие lz4 для больших колонок (`default_toast_compression`).
- Если станет тесно: старые годы — в сжатый архив на дешёвое хранилище, в базе только сводки.
- История в прошлое: 2026-11-09 владелец решил догрузить с 1 октября (для аналитики и базы
  поставщиков). Служба history, своим кругом; другая дата — `zakup backfill-from ГГГГ-ММ-ДД`
  (разовой командой), догрузка продолжится от самых старых записей вниз. Старые лоты сразу
  «увиденные» для подписок; техспецификации старых — только когда открыли на сайте.

- Сделано 2026-11-08: каждый клиент видит только свои ИИ-поиски; сотрудники — все поиски по лоту одной таблицей без повторов; поиски покупаются только к оплаченному тарифу.
- Идея владельца на потом: тариф подороже, где клиент видит и чужие поиски по лоту (экономит на поисках). Решать по статистике: сколько людей ищут по одним и тем же лотам.
